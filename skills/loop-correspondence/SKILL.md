## Read the loop

**A ⌘ B** reads **A in correspondence with B**. Bring the two sides into view and ask what one makes visible about the other. The relationship may support, qualify, contradict, or change the framing of either side. Keep disagreements and alternative readings visible when they matter. The relationship can be revisited as either side changes.

Read `i/c/w` as the plain-text spelling and `⌘` as the portable character; they mean the same. In designed Thyke material the rotated house glyph carries the same meaning. Use the surrounding text to tell correspondence from keyboard shortcuts such as `⌘C` or `⌘⇧P`. Inside a quotation, a code span or an example, preserve the original wording and act on the loop only if the surrounding request calls for it. A sentence that merely mentions the character ("can we make the ⌘ bigger?") is not a loop.

## The forms

| Written | Read it as |
| --- | --- |
| `A⌘B` or `A ⌘ B` | A in correspondence with B. |
| `⌘B` | B in correspondence with something left unsaid. Take the other side from the sentence around the loop ("summarise ⌘B" is about B itself); only when the loop stands alone is it the work at hand. |
| `A⌘` | A, with the other side open. Ask, or propose what it could be set against. |
| `A⌘B⌘C` | Several on one string. How they pair up is part of the reading: all together, or each with its neighbour. Say which you took. |
| `"a question or remark"⌘B` | Double quotes are the person's own words, new in this message: a question or claim set against B. Do not go looking for them as a document. |
| `[a loose description]⌘B` | Square brackets refer to something that exists; find it. |
| `https://…⌘B` | A link or a file path is already an address; read it. |
| `⌘` alone | A request for instructions: explain briefly how the loop is used. |

A side written like `notion:some-title` or `scuba:beginning…end` is a handle: a source and a shortened title. If you cannot open it, say so and work from what the person can paste.

## Follow an existing loop

1. Identify the sides. Use the current conversation, supplied excerpts and accessible links. Prefer the passage, observation or version that bears directly on the relationship. If a side is ambiguous, ask only when choosing the wrong one would materially change the reading. Say which source is missing or inaccessible and what can still be inferred.
2. Explain what changes when you read the sides together. Name the relationship in plain language and connect it to the relevant evidence. Distinguish what the sources say from your inference. When the sides disagree, retain who said what and which question remains open.
3. Match the response to the task. A single sentence can explain a small connection. For a handoff or a decision, carry forward the source links or exact excerpts, the reason they were joined, and any unresolved point the next reader needs.

## With the One Infinite Loop mod, and without it

Where the One Infinite Loop mod is installed (Claude Code), a message with a loop arrives with a block that begins `[one-infinite-loop] Loops found in this message.` It lists each loop's form and, for each side, what the mod found: `resolved` with a source, title and address; `ambiguous` with a few candidates; `missing`; or `as written` for the person's own quoted words. Use those addresses instead of searching again, ask which candidate was meant when it matters, and treat `missing` as yours to find. The block never says how to read the loop. That stays with you and the person.

Everywhere else (other Claude apps, ChatGPT, any model reading this file) there is no such block and nothing is resolved for you. Work from the text: the sides are whatever the person wrote, linked or pasted. Ask for an excerpt when a side is only a name you cannot open.

## Use the loop yourself

You can introduce `A ⌘ B` in your own analysis, notes or handoffs when the pairing helps someone see a qualification, recover context, or decide what to check next. Pair specific fragments and write one sentence explaining why they belong together. Mark relationships you propose as suggestions until a person adopts them or the evidence establishes them.

When bringing two agents' contributions into correspondence, keep each contribution attributable, identify where they converge or disagree, and point back to the underlying material. A loop can be passed to another agent as two references and a reason to read them together. Follow the task's existing permissions for fetching sources, editing records, or contacting others.

## Examples

- **Bring in two sources.** `⌘notion:essay-draft ⌘scuba:scenario-note` are two separate loops: each source is set beside the sentence they stand in, or beside the current work when they stand alone. Use both in light of the task; do not assume they were set against each other.
- **Read two sources together.** `notion:essay-draft⌘scuba:scenario-note` asks how the two bear on each other. Identify what the scenario distinction in the note would change in the essay.
- **Claim ⌘ evidence.** `"Local AI gives us more control" ⌘ "Who can restore it when it fails?"` The second side makes clear which kind of control needs testing. Treat the question as a test and cite operational evidence when it is available.
- **Question ⌘ context.** `"What should we change?" ⌘ [review notes]` Read the relevant notes before proposing changes. If the notes are inaccessible, say so and ask for the relevant excerpt when it would change the answer.
- **One agent's synthesis ⌘ another's dissent.** Carry the disagreement and the source passage each relied on into the handoff. State what would resolve the disagreement if the available material points to a test.
